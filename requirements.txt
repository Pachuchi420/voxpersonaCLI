# Backend service dependencies (BackService.py + friends)
# Target: macOS (Apple Silicon), TTS engine selectable at runtime (kokoro or chatterbox)
#
# DO NOT `pip install -r` this file directly -- run `./install.sh` instead.
# parakeet_mlx declares numpy>=2.2.5 and chatterbox-tts declares numpy<2.0.0;
# pip's resolver rejects that combination in one joint solve even though
# numpy 2.5.2 (what mlx-vlm itself pulls in) is verified to work fine with
# chatterbox-tts at runtime despite its stale declared ceiling -- see
# install.sh's comments. This file exists to document the exact verified
# pins, which install.sh installs in separate stages to avoid that resolver
# conflict.
#
# Requires Python 3.12 (NOT 3.14, which is too new for kokoro's misaki[en] ->
# spacy -> thinc -> blis chain to build wheels for yet). Every version below
# is pinned to an exact combination verified to install and import cleanly
# together on Python 3.12/macOS arm64 -- open-ended ranges here previously
# sent pip's resolver backtracking through hundreds of releases
# (transformers/accelerate/huggingface_hub together) until it hit
# "resolution-too-deep", and even pinning just those three still let
# kokoro/chatterbox-tts silently downgrade torch underneath torchvision
# afterwards (torchvision 0.28.0 needs torch==2.13.0, chatterbox-tts forces
# torch down to 2.6.0 -- transformers unconditionally imports torchvision
# for AutoProcessor, so that mismatch is a hard crash, not just a warning).
# If you need to change any single one of these, update install.sh's stages
# too and re-verify imports rather than bumping it in isolation.

# Core
websockets==16.0
numpy==2.5.2
torch==2.6.0
torchaudio==2.6.0
soundfile==0.14.0
silero-vad==6.2.1

# Transcription (macOS backend, auto-selected via platform.system() == "Darwin")
mlx==0.32.0
parakeet_mlx==0.5.2

# Gemma 4 E2B (GemmaService.py) -- shared by TranscriptionService's "gemma"
# backend and ResponseService's "gemma" engine. Runs on native MLX (not
# transformers/PyTorch) via mlx-vlm -- much lighter (a ~2GB 4-bit checkpoint
# vs. ~10GB for the bf16 transformers one) and avoids a bf16-on-MPS bug in
# transformers/PyTorch where the default "sdpa" attention kernel produced
# NaN/Inf logits with this model (see GemmaService.py's module docstring).
# Selecting the "gemma" backend/engine downloads mlx-community/gemma-4-e2b-
# it-4bit from Hugging Face on first use -- not gated, no login/token needed.
mlx-vlm==0.6.13

# transformers/accelerate/timm/huggingface_hub/torchvision below are NOT
# used directly by GemmaService.py anymore (mlx-vlm handles its own model
# loading) -- they're still here because kokoro/chatterbox-tts need
# transformers transitively, and this exact combination is verified to
# import cleanly despite chatterbox-tts 0.1.7 declaring transformers==5.2.0,
# accelerate==1.0.1 (predates ACCELERATE_MIN_VERSION==1.1.0 that transformers
# 5.15 requires), safetensors==0.5.3, and torch==2.6.0 as hard pins -- pip's
# own dependency metadata is stale here, not an actual runtime break.
transformers==5.15.0
accelerate==1.14.0
timm==1.0.28
huggingface_hub==1.27.0
torchvision==0.21.0

# TTS engines (DialogueService picks one via the `engine` constructor arg)
kokoro==0.9.4
chatterbox-tts==0.1.7

# TestChatUI.py only -- manual Tk test client, not used by BackService.py itself
